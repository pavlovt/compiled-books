# Final Tests: Answer Key

## Test 1

1.  **b.** A component is a function that runs once; the template’s reactive expressions become effects that update the DOM. There is no virtual DOM and no per-component re-run. (Ch. 1, Ch. 5)
2.  **b.** Runes are compiled only in `.svelte`, `.svelte.js` and `.svelte.ts` files; in a plain `.ts` file `$state` fails at runtime with `rune_outside_svelte`. (Ch. 1)
3.  **c.** A `$state` that is never reassigned or mutated compiles to a plain variable (sometimes inlined). Only state that changes becomes `$.state(...)`. (Ch. 2)
4.  **d.** Rune use, `<svelte:options runes />`, the `runes` compiler option and top-level `await` all imply runes mode. Merely importing `onMount` does not. (Ch. 1)
5.  **b.** `mount` and `hydrate` do not run effects synchronously; call `flushSync()` if you need them to have run. (Ch. 1)
6.  **c.** Plain objects and arrays are proxied recursively. Class instances, `Map`, `Set` and `Date` are not; use `SvelteMap` and friends from `svelte/reactivity` for reactive versions. (Ch. 3)
7.  **b.** `$state.snapshot` is a static deep clone with `structuredClone` semantics that honours `toJSON`. Uncloneable parts come back as originals with `state_snapshot_uncloneable`. (Ch. 3)
8.  **c.** Deriveds must be free of side effects; writing to outer state inside one throws `state_unsafe_mutation`. Only state created inside the derived may be written. (Ch. 4)
9.  **b.** Deriveds have been writable since 5.25, which enables optimistic UI. The assigned value stays until a dependency changes, then the derived is recomputed from its expression. (Ch. 4)
10. **b.** Effects run only in the browser, after DOM updates, batched in a microtask, and a returned function is the teardown. Computing values is the job of `$derived`. (Ch. 4)
11. **a.** Dependencies are those read during the last run. With `a` false, `b` is never read, so only `a` is a dependency until `a` becomes true. (Ch. 4)
12. **b.** `onDestroy` is the only lifecycle function that runs on the server; `onMount` and effects do not. (Ch. 4, Ch. 14)
13. **b.** `10` then `12`. State writes are synchronous and reading a derived pulls a fresh value, so no flush is needed. (Ch. 4)
14. **c.** `Ada Grace`. Destructuring copies the current value, so `name` is a plain string that never updates. (Ch. 3)
15. **a.** `start`, `after root`, `effect 3`, `end`. The effect is scheduled, not run, when created; both writes land in one batch and `flushSync` runs the effect once with the latest value. (Ch. 4, Ch. 5, Ch. 16)
16. **a.** `len 2`, `3`, `len 4`. `$state.raw` is not a proxy: `push` mutates the array without signalling anyone, so the effect does not re-run (and the array length is 3). Reassigning triggers the effect. (Ch. 3)
17. **b.** `parity 1`, `parity 0`. `n = 3` leaves `parity` at 1; the derived’s value did not change, so the effect is skipped. `n = 4` changes it to 0. (Ch. 4, Ch. 5)
18. **b.** `run 1`, `cleanup 1 1`, `run 2`, `cleanup 2 2`. Since 5.23 a teardown sees the values from the run it belongs to, even though `a` has already been written; the last cleanup comes from `stop()`. (Ch. 4, Ch. 5)
19. **b.** `false false -1`. `push` stores a proxy of the object, so the original object is neither `===` to the stored element nor found by `includes` or `indexOf`. (Ch. 3)
20. **b.** `{"text":"milk"}`. `$state` class fields compile to prototype accessors over private fields, so `done` is not an own enumerable property and is absent from `JSON.stringify`. (Ch. 3)
21. `state_referenced_locally`. `label` captures only the initial value of `count`. Use ``let label = $derived(`Items: ${count * 2}`);``, or read `count` directly in the markup. (Ch. 3, Ch. 7)
22. `effect_update_depth_exceeded`. `push` reads `length` and then writes, so the effect depends on and invalidates the same state and loops. Fix: use a handler or a different structure, or read with `untrack(() => history.push(count))` so only `count` is a dependency. A `$derived` or an event handler is usually the better design. (Ch. 4, Ch. 5)
23. `onMount` only honours a returned cleanup when the callback is synchronous. An `async` callback returns a promise, so the cleanup function is ignored. Make the callback synchronous (and start the interval directly), or use an `$effect` with a teardown. (Ch. 4)
24. Only values read synchronously during the effect run are tracked. `count` is read inside the `setTimeout` callback, after the run has finished, so it is not a dependency. Read it into a local variable before the `setTimeout`, or use `$effect` with that local. (Ch. 4)
25. First, `$derived` is lazy, memoised and always consistent with its inputs, without an extra flush; an effect would write state after the DOM update, causing an extra update cycle and a briefly stale value. Second, it works during server rendering, whereas effects never run there, so the effect version would render an empty name in the server HTML. (Ch. 4, Ch. 14, Ch. 18)
26. Choose `$state.raw` for large data that is replaced wholesale (API results, big lists), because it avoids proxy creation, per-property sources and trap overhead. You give up in-place mutation (`push`, `item.x = ...` do nothing) and fine-grained updates: every reader re-runs on reassignment. (Ch. 3, Ch. 18)
27. A derived’s change is only propagated when its new value differs from the old one (`===`-style equality). A write marks readers `MAYBE_DIRTY`; when pulled, the derived re-runs and downstream effects re-run only if its value changed. A derived that builds a new array or object always returns a new identity, so everything downstream re-runs even if the contents are equal; derive a primitive (for instance a count or key) when you want the cut-off. (Ch. 4, Ch. 5, Ch. 18)
28. Products: `$state.raw` (large, replaced wholesale). Query: `$state('')` bound to the input. Filtered list: `$derived` from products and query. Count: `$derived` of the filtered length (or read `.length` directly in the markup). No `$effect` is needed; loading products is done in a handler or an `onMount`/`await` pattern, not by syncing state in effects. (Ch. 3, Ch. 4, Ch. 18)
29. A reassigned `$state` cannot be exported (`state_invalid_export`), because the compiler works one file at a time and an importer would receive the underlying signal object instead of its value. Option 1: export an object and mutate it (`export const cart = $state({ items: [] as Item[] })`, with `cart.items = []` in `clear()`). Option 2: keep the state private and export functions or a class with a `$state` field (`class Cart { items = $state<Item[]>([]); clear() { this.items = []; } }`, exported as a single instance) or getters (`export const getItems = () => items`). (Ch. 1, Ch. 3, Ch. 12)

6.  **b.** On the server `{#await}` renders only the pending branch; the `:then` branch is rendered on the client (a non-promise value goes straight to `:then`). (Ch. 6, Ch. 14)
7.  **c.** Snippets support defaults and destructuring but not rest parameters (`snippet_invalid_rest_parameter`); take an array instead. (Ch. 7)
8.  **b.** `{@render}` of `undefined` throws `invalid_snippet`. For optional snippets use `{@render footer?.()}` or `{#if footer}`. (Ch. 7)
9.  **b.** Binding `undefined` to a bindable prop that has a fallback throws `props_invalid_value`. Initialise the parent’s state with a real value. (Ch. 7, Ch. 8)
10. **b.** `bind:group` on checkboxes yields an array of the checked inputs’ `value`s; on radios it yields the selected value. It only works within one component. (Ch. 8)
11. **c.** The 5.57.2 runtime reports `null` for an empty number input (the docs say `undefined`), so type the state as `number | null`. (Ch. 8)
12. **b.** Only `scrollX` and `scrollY` are writable; the other window bindings are read-only. (Ch. 9)
13. **a.** Boolean attributes (`hidden`, `disabled`) follow truthiness, so `false` and `0` omit them. For other attributes only `null` and `undefined` omit the attribute; `aria-hidden={false}` renders `"false"`, and the empty string is kept. (Ch. 6)
14. **b.** `null` and `undefined` render as an empty string in Svelte 5; `0`, `false` and `NaN` are stringified. (Ch. 6)
15. **a.** `class` takes clsx-style arrays and objects; falsy array entries are dropped (including `0`). A bare `false` is stringified as `"false"`, while `undefined` and an empty array omit the attribute. The `style:` directive beats the `style` attribute. (Ch. 6, Ch. 10)
16. **b.** `1||{"c":"z"}`. The fallback is used only for `undefined`, so `a` becomes 1; `null` is a real value and renders as empty text; `c` lands in the rest props. (Ch. 7)
17. **b.** `manual`, `button`, `outer`. Declared handlers run from a single delegated listener on the root, so a listener added directly on the element fires first, and `stopPropagation` there would block the delegated ones. Use `on` from `svelte/events` to keep ordering predictable. (Ch. 6, Ch. 9)
18. **c.** `oninput "hi"`, then `effect "hi"`. The binding updates state before the `oninput` attribute handler runs, and effects flush afterwards. (Ch. 8)
19. **b.** An attachment re-runs, with cleanup first, when state read in its factory expression (`label`) or inside the attachment function (`other`) changes. (Ch. 9)
20. **a.** `<ul><li>0:a</li><li>5:b</li></ul>`. Snippet parameters may have defaults. (Ch. 7)
21. `each_item_invalid_assignment`: in runes mode you cannot bind to or reassign the each variable. Bind to the array element instead: `{#each names as _, i}<input bind:value={names[i]} />{/each}`, or make the items objects and bind to a property (`bind:value={item.name}`). (Ch. 6, Ch. 8)
22. Spread order matters: the later attribute wins, so the internal `onclick` replaces `rest.onclick`. Destructure `onclick` from props and call both: `<button {...rest} onclick={(e) => { clicks++; onclick?.(e); }}>`. Put local handlers after the spread and forward the external one. (Ch. 7)
23. Actions cannot be used on components (`component_invalid_directive`). Use `{@attach tip('Save')}`: on a component it becomes a Symbol-keyed prop, so the child must spread its rest props onto the element that should receive it. (Ch. 9)
24. `bind_invalid_checkbox_value`. `bind:value` on a checkbox is not allowed; use `bind:checked` (or `bind:group` for sets). (Ch. 8)
25. Svelte delegates `click` and similar events to a single listener on the app root, so a manual listener on an inner element runs before the delegated handlers; its `stopPropagation` stops the event reaching the root, so delegated handlers never fire. Use `on(element, 'click', handler)` from `svelte/events`, which preserves ordering relative to declarative handlers, and give synthetic events `bubbles: true`. (Ch. 6, Ch. 9)
26. (1) An action runs once, untracked, and its argument is not reactive (unless it uses its own effects or the legacy `update`); an attachment runs inside an effect and re-runs, with cleanup, when state it reads changes. (2) Attachments can be used on components (Symbol-keyed props forwarded by spreading); actions cannot. (3) An attachment may be conditional (falsy values are ignored), may appear several times and may be created by factories; `fromAction` adapts old actions. (Ch. 9)
27. Snippets are typed (`Snippet<[T]>`), take parameters with defaults and destructuring, can be passed as ordinary props or implicitly as children, can be declared and rendered anywhere in the same component (including recursively), and can be exported from `<script module>`; slots are named placeholders with `let:` and cannot be used as values. (Ch. 7)
28. A good answer: `open` as `$bindable(false)` (or `open` plus `onclose` callback), `title` string, `children` snippet for content, optional `footer` snippet rendered with `{@render footer?.()}`, `onclose` callback prop instead of an event, rest props spread on the root `<dialog>`; expose a `focusClose()` export reachable through `bind:this`, or move focus with an attachment. Use native `<dialog>` with `showModal()` for focus trapping and Escape handling, label it with `aria-labelledby` from `$props.id()`, and restore focus to the opener on close. Type with `interface Props` and `Snippet`. (Ch. 7, Ch. 8, Ch. 17)
29. Use a function binding `bind:value={() => format(digits), (v) => (digits = v.replace(/\D/g, ''))}` so state stays digits-only while the field shows the formatted text, plus `defaultValue` so `form.reset()` restores the original. Avoid an `$effect` that rewrites state from state (extra flush, risk of loops and caret jumps). (Ch. 8, Ch. 4)
